# JARVIS predictions and VISION

The dynamics site (`https://tamusrt.github.io/dynamics/`) has five tabs:

| Tab | What it shows |
| --- | --- |
| **History** | OpenRocket results for every committed version of each design |
| **Flight plots** | Any OpenRocket flight variable against another, for the latest version |
| **Changelog** | What changed in each `.ork` file, commit by commit |
| **JARVIS predictions** | Jarvis's simulation of the current design, next to OpenRocket |
| **VISION** | The same simulated flight, replayed in 3D |

This folder builds the JARVIS predictions and VISION tabs. The pages are also available on their own at
`/predictions/` and `/predictions/viewer/`.

## Terms

- **Jarvis** is the team's flight simulator, in the [`flight_sim`](https://github.com/tamusrt/flight_sim) repository.
  On the JARVIS predictions tab it simulates the whole flight in six degrees of freedom (6-DOF), from the launch rail
  to landing.
- **VISION** replays that same simulated flight in 3D.
- **OpenRocket** results are OpenRocket's own simulation of the same design, used for comparison.
- **RASAero table** (`*_aero.csv`) is the aerodynamic data Jarvis flies with: drag, lift and center of pressure
  against Mach number and angle of attack, generated by RASAero II.

## What the JARVIS predictions tab shows

- A chart of altitude, speed, Mach number, acceleration, stability margin or drag for the selected launch conditions,
  with Jarvis and OpenRocket as separate lines. **Difference from OpenRocket** shows the gap over time.
- **Apogee by launch condition**: every simulation saved in the `.ork` (each has its own wind and launch rail).
- Ascent and descent tables, with grey rows for the difference between Jarvis and OpenRocket.
- Warnings, for example when the stability margin is below the team minimum or the RASAero table is out of date.

## Inputs

| Input | File (SRT14) | Used for |
| --- | --- | --- |
| OpenRocket design | `IREC_2027/OR/2027_OR.ork` | Geometry, masses and launch conditions |
| RASAero table | `IREC_2027/RASA/ignis_2027_aero.csv` | Drag, lift and center of pressure |
| RASAero design | `IREC_2027/RASA/rasaero.CDX1` | The shape the RASAero table was made for |
| Motor | `default_motor` in `sim_config.json`, otherwise the newest `.eng` or `.rse` in `IREC_2027/Thrust Curves/` | Thrust and motor mass |

Paths are relative to `aero_modeling/` and are set in `aero_modeling/whatif_config.json`.

- **OpenRocket results** come from the History tab (the latest successful run of each simulation). When no History
  site is available, the results saved in the `.ork` are used instead, and the page says which.
- **Motor.** Jarvis uses the same motor as the History tab when one is set. To force a specific file, add
  `"motor": "<file>"` to the rocket in `whatif_config.json`.
- **Stability margin** is counted as on the History tab: from rail exit to apogee, only above 30 m/s.
- **Geometry.** Jarvis always uses the current `.ork`. If it differs from `rasaero.CDX1`, the page corrects the
  aerodynamics for the difference, lists the differences and warns you. Regenerate the table with Update CSV.
- **Descent.** The design has no parachutes yet, so Jarvis uses the Sol Invictus recovery system as a placeholder,
  and OpenRocket's descent is not shown.

### Limitations

- The geometry corrections are first-order. Trust trends more than the last percent.
- RASAero's subsonic drag is lower than OpenRocket's, so Jarvis predicts a higher apogee. Compare designs with each
  other rather than with OpenRocket.
- The wind is constant, and the aerodynamic table is for the motor off.

## When the site rebuilds

The workflow `.github/workflows/openrocket-sim.yml` rebuilds and publishes the site when a push to `main` changes:

- a `.ork`, `.eng`, `.rse`, `.csv` or `.CDX1` file under `aero_modeling/`
- `aero_modeling/whatif_config.json` or `aero_modeling/sim_config.json`
- anything in `tools/whatif/`, or `tools/openrocket/or_ci.py`

Pushes to other branches run the simulations and post a comment, but do not publish.

To rebuild by hand: **Actions → OpenRocket simulation check → Run workflow** (branch `main`).

### When `flight_sim` changes

The workflow uses the `flight_sim` branch named by the repository variable `FLIGHT_SIM_REF` (default `main`).
`flight_sim` tells this repository to rebuild when that branch changes (its `notify-dynamics.yml` workflow), which
needs a one-time setup in `flight_sim`: a repository secret `DYNAMICS_DISPATCH_TOKEN`, holding a fine-grained personal
access token with **Contents: Read and write** on this repository only. Without it, rebuild by hand after changing
`flight_sim`.

## Jarvis on the History tab

The History tab shows Jarvis as a **dashed line** next to each OpenRocket line. These points come from a faster,
simplified version of Jarvis, run on every committed version of the design with the RASAero table as it was at that
commit and today's motor, so the line reflects design changes only. It should follow OpenRocket's trend; it is not
expected to match every number. The **Jarvis** button above the chart hides the dashed lines.

The results are written to `site/jarvis_by_commit.json` by `flight_sim.whatif.commits`. If this step fails, the History
tab still works without the dashed lines.

## Update CSV: regenerate the RASAero table

Use this after the rocket's shape changes. It's at the bottom of the JARVIS predictions tab. You need a Windows computer
with RASAero II, a copy of this repository and `flight_sim` installed.

**First time only:** `pip install pyautogui`, and install `flight_sim` into the same Python
(`pip install -e <path to flight_sim>`).

1. **Start the helper.** In Command Prompt, from the `dynamics` folder, run `python tools\whatif\local_helper.py`.
   The page shows when it is connected.
2. **Run RASAero.** In OpenRocket, export the design to RASAero over `rasaero.CDX1` (the page shows its full path), and
   open it in RASAero II. Click inside RASAero, return to the page and click **Create the 31 RASAero files**. Don't use
   the keyboard or mouse until the page says **Finished**. Moving the mouse to a corner of the screen stops it.
3. **Update the table and publish.** Click **Update the table and publish**. The helper converts the results into the
   CSV, rebuilds the page, commits and pushes the CSV and `rasaero.CDX1`, and closes. The site updates in about
   10–20 minutes.

Before step 2 starts, the helper checks `rasaero.CDX1` against the `.ork` (`fix_cdx.py`). If it has to correct the file,
it stops without typing anything, because RASAero still has the old version open: open the file again in RASAero
(**File → Open**) and click the button again. It also stops if RASAero's window title names a different `.CDX1`.
If the rebuild fails, the previous CSV is restored.

To review changes before publishing, start the helper with `--no-publish`; the page then lists the git commands to run.

The helper only listens on `127.0.0.1` and only accepts requests from `https://tamusrt.github.io` and from itself. If
Chrome asks to allow access to devices on your local network, click **Allow**. If the live page can't reach the helper,
use `http://127.0.0.1:8765/predictions/` instead.

## The JARVIS message in Discord

Each build on `main` sends a **JARVIS simulation** message with a link to VISION, Jarvis's apogee for each launch
condition (next to OpenRocket's), and a ⚠️ line when:

- the stability margin falls below 1.0 caliber,
- the RASAero table doesn't match the rocket, or
- OpenRocket's saved runs used a different motor from the motor file.

`vision_shot.py` takes a picture of the whole flight in VISION for the message (published as `predictions/vision.png`).

- **With a Discord webhook (recommended)**, the message is posted straight to the channel, with the picture. In
  Discord, open the channel settings → **Integrations → Webhooks → New Webhook → Copy Webhook URL**. In this
  repository, add it as a repository secret named `DISCORD_WEBHOOK_URL` (**Settings → Secrets and variables →
  Actions**). Keep the URL private: anyone with it can post in the channel.
- **Without a webhook**, the message is a commit comment, which the Discord GitHub bot shows as text only.

## Checks

Every push that changes `tools/whatif/`, `tools/openrocket/`, `aero_modeling/` or the workflow runs:

- **Page tests** (`tools/openrocket/tests/`): the History page's code against sample data.
- **Build tests** (`tools/whatif/tests/`): the predictions build, the Update CSV helper and the site status script.
- **Browser test** (`tools/whatif/tests/browser_test.py`): opens the built site in Chromium and checks every tab,
  including that VISION draws a 3D scene and that no page has script errors or missing files. Screenshots are saved in
  the run's artifacts (`browser-test-pictures-...`).

## If a build breaks a page

If a push breaks the JARVIS predictions tab or VISION, the workflow keeps the last working version of that page on the
site, shows a red **Error** bar at the top of every tab saying what broke (with a link to the run), and still publishes
the rest of the site. The bar disappears after the next clean build. If the History tab itself breaks, nothing is
published and the live site stays as it is. This is handled by `site_status.py`. If the site is not at
`https://<owner>.github.io/<repo>`, set the repository variable `LIVE_SITE_URL`.

## Adding a rocket

Add an entry under `rockets` in `aero_modeling/whatif_config.json` with `ork`, `aero`, and `motor_dir` or `motor`.
`rasaero`, `sim` and `alpha_dir` are optional (`alpha_dir` is needed for Update CSV). The `default` rocket is at
`/predictions/`; others are at `/predictions/<key in lowercase>/`.

## Building locally

```
pip install -e <path to flight_sim>
python tools/whatif/build_site.py --config aero_modeling/whatif_config.json --site site
python tools/whatif/tests/test_build_site.py
python tools/whatif/tests/test_local_helper.py
python tools/whatif/tests/test_site_status.py
pip install playwright
python -m playwright install chromium
python tools/whatif/tests/browser_test.py --synthetic
python tools/whatif/tests/browser_test.py --site site --require-predictions --shots pictures
```

Then open `site/predictions/index.html`. `build_site.py --dry-run` prints the commands and the motor it would use.
